第一章　前言
1.1　研究動機

現代大學生每學期選課時，往往面對數百門課程卻難以判斷哪些最適合自己。傳統的課程查詢系統僅能提供基本的課程資訊，如開課時間、學分數與授課教師，缺乏對課程難度、授課品質與個人先備知識的客觀評估依據。

此外，學生通常需要在多個平台之間切換，包含校務系統、Dcard 討論版與學長姐的非正式口耳相傳，才能蒐集到足夠的選課參考資訊。這種資訊分散的現象不僅浪費大量時間，也可能導致選課決策品質不佳，影響整體學習效益。

根據我們對逢甲大學同學的非正式調查，超過七成的學生表示在選課時曾感到困惑或無所適從，其中最常見的困擾包括：不知道自己的先備知識是否足以應付課程、不知道授課老師的教學風格是否符合自己的學習習慣，以及不確定課程是否能幫助自己達成修課目標。

有鑑於此，我們認為有必要建立一個整合式的 AI 輔助選課平台，讓學生能夠在同一個介面內完成搜尋、評估與排課，大幅提升選課效率與滿意度。

3
1.2　研究方向

本專題以逢甲大學學生為主要使用對象，規劃開發一套名為「逢甲選課助手（Course Search）」的 Web 應用程式。系統整合以下四大核心功能：

  • AI 課程分析：使用者輸入個人背景與修課目標後，系統呼叫 Claude / GPT 等大型語言模型，提供課程適合度分析、預期難度評估與個人化修課建議，協助學生在選課前做出更有把握的決策。
  • 課程搜尋與篩選：整合逢甲完整課程資料庫（4,000 筆以上），支援關鍵字、課程標籤（60 餘種）、學分數範圍、開課時間與教師名稱等多維度篩選，快速定位目標課程。
  • AI 排課規劃器：使用者只需以自然語言描述修課目標，AI 即可自動從全校課程中推薦最符合需求的組合，並即時偵測時間衝堂，以視覺化週課表呈現建議結果。
  • 社群評分整合：透過自動爬蟲定期蒐集 Dcard 上的課程討論文章，利用 AI 彙整學長姐的修課心得與評分，轉化為結構化的課程評價指標，作為選課的重要輔助參考。

系統以 Web 應用程式形式提供，不需要安裝任何額外軟體，學生只需透過瀏覽器即可使用，大幅降低使用門檻。

4
1.3　系統特色與創新

相較於現有的選課輔助工具，本系統具備以下幾項主要特色與創新：

① 多 AI 提供者架構

系統支援 Anthropic Claude、OpenAI GPT 與 OpenRouter 等多個 AI 提供者，可依需求彈性切換，確保服務穩定性，同時降低對單一 API 的依賴風險。

② 前後端分離 + API Key 保護

所有 AI API Key 均存放於伺服器端，前端不會接觸任何敏感金鑰。前端部署至 Vercel CDN，後端部署至 Railway，兩者透過 HTTPS 通訊，確保資料安全。

③ PDF 課表智慧解析

支援上傳 PDF 格式課表，系統透過 OCR 技術（Mistral OCR 或 Cloudflare AI）自動解析課程名稱、教師、學分與節次，免去手動輸入的繁瑣步驟。

④ 深色 / 淺色模式 + 中英雙語

介面支援一鍵切換深色與淺色模式，並提供完整的中文與英文介面切換功能，照顧不同使用習慣的學生，包含國際交換生。

⑤ 逢甲 NID OAuth 整合

系統已整合逢甲大學 NID（Network Identity）OAuth 登入介面，學生可直接使用學號帳號登入，享有個人化的收藏紀錄與 AI 分析歷史查閱功能，帳號資料與逢甲校務系統完全同步。

第二章　市面分析
2.1　AI 輔助教育工具的趨勢

近年來，生成式 AI 的快速普及對教育領域帶來顯著的正面影響。根據 Statista 統計，全球 AI in Education 市場規模於 2023 年已超過 40 億美元，並預計於 2030 年成長至約 800 億美元，年均複合成長率（CAGR）超過 40%。

在高等教育方面，各大學與科技公司開始積極將 AI 技術整合至學習輔助工具中。常見的應用方向包含：智慧問答系統、自動作業批改、學習進度追蹤、個人化學習路徑規劃，以及課程推薦系統。

在課程推薦領域，美國多所頂尖大學已導入 AI 推薦引擎，根據學生過往修課紀錄、成績分布與職涯目標，自動推薦下學期最適合的課程組合。這類系統不僅提升學生的選課效率，也有助於學校掌握整體課程供需狀況。

在台灣，雖然各大學已建置基本的課程查詢系統，但 AI 輔助選課的功能相當有限。多數平台仍停留在基本關鍵字搜尋的階段，缺乏個人化推薦與社群評分的整合。隨著生成式 AI 技術的普及，AI 選課助手正逐漸成為一個具備高度實用性與市場潛力的開發方向。

本專題即是針對這一趨勢，以逢甲大學為試驗場域，開發一套結合 AI 分析、社群評分與排課規劃的整合式選課助手，期望能為台灣高等教育的數位化轉型提供實際可行的參考案例。

2.3　本系統的定位與差異化

綜合以上分析，現有工具各有其侷限：校務系統功能基礎但缺乏智慧化，Dcard 有豐富內容但缺乏系統化整理。本系統的定位是同時解決這兩個問題，以下列出三個核心差異化優勢：

差異化優勢一：資訊整合

將分散在校務系統、Dcard 與學長姐口耳相傳中的選課資訊，統一整合至單一平台，讓學生不再需要在多個管道之間來回切換，大幅縮短資訊蒐集時間。

差異化優勢二：AI 個人化分析

不同於靜態的評分數字，本系統的 AI 分析功能能針對每位學生的個人背景（如修過的科目、技能程度、修課目標），提供量身訂作的適合度評估與具體建議，讓選課決策更有依據。

差異化優勢三：零安裝 Web 應用

以純 Web 形式提供服務，無須安裝任何 App 或插件，在任何裝置的瀏覽器上皆可存取，降低使用門檻，讓更多學生能夠輕鬆上手。

本系統目前鎖定逢甲大學學生作為主要使用族群，未來若學校 API 開放，亦可擴展至其他大學，具備良好的橫向擴充潛力。

第三章　使用技術
3.1　前端技術
HTML5 / CSS3 / JavaScript（ES6+）

前端採用純 HTML5 + CSS3 + 原生 JavaScript 架構，不依賴 React、Vue 等大型前端框架，以降低打包複雜度並提升部署彈性。所有 UI 邏輯均封裝於單一 app.js 檔案（約 4,800 行），以 IIFE 模式避免全域命名污染。

Tailwind CSS

樣式採用 Tailwind CSS CDN 版本進行快速開發，搭配自訂設定檔（tailwind.config）擴充 Notion 風格色系與深色模式色票。深色模式以 CSS class 切換實現，不依賴媒體查詢。

Google Fonts

整合 Google Fonts 的 Inter（英文無襯線）與 Noto Sans TC（中文）字型，確保中英文排版在各系統上均有一致的視覺呈現效果。

自製 i18n 國際化模組（i18n.js）

開發自製的輕量級多語系模組，支援繁體中文與英文介面切換，翻譯字典約涵蓋 300 餘組文字對應，透過 data-i18n-text 屬性標記需翻譯的 DOM 元素，切換時即時替換文字內容，無需重新載入頁面。

Vercel 靜態部署

前端靜態檔案透過 vercel.json 設定，部署至 Vercel 全球 CDN 網路。Vercel 提供自動 HTTPS、邊緣節點快取與即時預覽部署（Preview Deployment）功能，每次 Git Push 後自動觸發新版本部署。

9
3.2　後端技術
Node.js

後端執行環境採用 Node.js，利用其非同步 I/O 特性高效處理並發的 AI API 請求。使用 ES Module（import/export）語法撰寫，與現代 JavaScript 生態系保持一致。

Express.js v5

Web 框架採用 Express.js 第五版，提供簡潔的路由管理與中介軟體（middleware）機制。主要功能包含靜態檔案服務（前後端合一模式）、JSON 請求解析、錯誤處理與 API 路由分發。

安全性套件
  • Helmet.js：自動設定 Content-Security-Policy、X-Frame-Options、HSTS 等 HTTP 安全標頭，防禦常見的 Web 攻擊向量。
  • CORS：透過 cors 套件設定允許的跨域來源，部署時限定僅接受來自 Vercel 前端網域的請求。
  • express-rate-limit：對 AI 分析等高成本 API 端點設定請求限速，防止濫用與暴力攻擊。
Railway 雲端部署

後端服務部署至 Railway 平台，Railway 自動偵測 Node.js 專案並執行 npm start。環境變數（API Key、資料庫連線字串等）透過 Railway 的環境變數管理介面注入，不暴露於原始碼中。Railway 提供自動重啟、健康檢查與即時日誌監控等功能。

3.3　AI API 整合

本系統設計為多 AI 提供者架構，可依環境變數（AI_PROVIDER）彈性切換不同 AI 服務：

Anthropic Claude API（預設）

預設使用 Anthropic Claude API，呼叫 claude-3-5-haiku 等模型進行課程適合度分析與排課關鍵字提取。回應要求以繁體中文輸出，並以結構化 JSON 格式回傳分析結果，方便前端直接解析使用。

OpenAI GPT API

作為備用提供者，使用 OpenAI-compatible API 介面，可指定 gpt-4o-mini 等模型。切換至 OpenAI 時系統行為與 Anthropic 版本保持一致，對前端完全透明。

OpenRouter

支援透過 OpenRouter 平台使用多種開源與商業模型。特別用於 PDF 課表解析功能，可選擇 mistral-ocr（適合掃描型 PDF）或 cloudflare-ai（低成本選項）作為 OCR 引擎，解析上傳的課表圖片並提取結構化課程資訊。

提供者主要用途環境變數

OpenAI GPT備用 AI 服務OPENAI_API_KEY

3.4　資料庫與安全機制
PostgreSQL + node-postgres

使用 PostgreSQL 作為關聯式資料庫，透過 pg（node-postgres）套件建立連線池（Connection Pool）。連線字串透過環境變數 DATABASE_URL 注入，系統啟動時自動判斷部署環境並決定是否啟用 SSL 加密連線。所有資料表於伺服器啟動時自動建立（CREATE TABLE IF NOT EXISTS），無需手動執行 migration。

JWT 認證機制

使用者登入後由後端核發 JSON Web Token（JWT），Token 存放於瀏覽器 localStorage。每次呼叫需要認證的 API 時，前端自動在 Authorization Header 帶入 Bearer Token，後端驗證 Token 有效性後才處理請求，防止未授權存取。

逢甲 NID OAuth

系統已預留逢甲大學 NID OAuth 2.0 登入流程，包含 /api/auth/login 與 /api/auth/callback 端點。待學校資訊處正式開放相關 API 後，即可讓學生以逢甲學號帳號登入，享有個人化功能。NID API KEY 每年 7/31 到期，需定期重新申請。

Resend Email 服務

意見回饋功能透過 Resend API 傳送 Email 通知至指定信箱。Resend 提供高送達率與詳細的發送紀錄，比傳統 SMTP 設定更為簡便。收件信箱由環境變數 FEEDBACK_EMAIL 設定，無需修改程式碼即可更換。

第四章　系統開發
4.1　UI 設計概念

本系統的 UI 設計以 Notion 風格為主要靈感，追求簡潔、現代且資訊密度適中的視覺體驗。設計原則如下：

  • 色系：淺色模式以白色（#ffffff）與米白（#f7f7f5）為背景，搭配深灰文字（#37352f）與藍色強調色（#2eaadc）；深色模式以深灰（#191919 / #202020）為主，確保長時間使用時的視覺舒適性。
  • 字型：中文採用 Noto Sans TC，英文採用 Inter，兩者均為現代無襯線字型，在螢幕上具有良好的可讀性。
  • 間距：採用一致的 8px 基準間距系統（Tailwind CSS spacing scale），確保元素之間的視覺節奏感。
  • 互動反饋：按鈕與卡片在 hover 時有輕微的背景色變化與過渡動畫（transition-colors duration-150），提升操作的回饋感。
  • 響應式設計：版面以 max-width: 7xl（1280px）為主要容器，在桌機與平板上均有良好呈現。

整體版面採用垂直分區結構，從上到下依序為：頂部導覽列、搜尋篩選區、課程卡片列表、AI 排課規劃器，以及底部意見回饋浮動按鈕。各區塊職責分明，降低使用者的認知負擔。

4.2　各功能頁面說明
頂部導覽列（Header）

左側顯示品牌識別（FCU 藍底白字方塊 + 「逢甲選課助手」文字），右側依序排列：NID 登入按鈕、語言切換器（中 / EN）、收藏清單（含未讀計數徽章）、深色模式切換按鈕。所有按鈕均採用圓角設計，hover 狀態有背景色變化提示。

課程搜尋區

提供關鍵字輸入框（即時搜尋，300ms debounce）、課程標籤多選篩選（60+ 種，可橫向捲動）、學分數範圍滑桿，以及「重置篩選」快捷按鈕。搜尋結果計數即時顯示在搜尋框旁。

課程卡片列表

每張課程卡片以卡片式（Card）設計顯示課程名稱、授課教師、學分數、開課時間、系所，以及 Dcard 社群評分（星等 1–5 + 綜合分數 0–100）。右上角的收藏按鈕（愛心圖示）可一鍵加入收藏清單；「AI 分析」按鈕點擊後展開側邊分析面板。卡片支援無限捲動（Infinite Scroll）自動載入更多結果。

AI 排課規劃器（Planner）

使用者在文字輸入框描述修課背景與目標，或上傳 PDF 課表，AI 即自動分析並推薦課程組合。推薦結果以視覺化週課表（7×13 格 = 週一至週五 × 第 1–13 節）呈現，衝堂課程以紅色標示警告。

收藏側欄 / 意見回饋

收藏側欄為右側滑入式面板，列出所有收藏課程並支援一鍵匯出。意見回饋以底部右下角浮動按鈕呈現，點擊後展開含類型選擇、內容輸入與聯絡方式的回饋表單。

系統使用 PostgreSQL 資料庫，共設計六張資料表，於伺服器啟動時自動建立：

4.6　AI 課程分析功能

AI 課程分析是本系統的核心功能之一。使用者點擊課程卡片上的「AI 分析」按鈕後，系統展開輸入面板，引導使用者輸入個人修課背景（如已修過哪些課、目前的程式能力、修這門課的目的等），再將這些資訊連同課程基本資料一起送往後端的 /api/analyze 端點。

後端組合 System Prompt 與使用者資訊後，呼叫 AI 模型進行分析。Prompt 的設計要求 AI 扮演「逢甲大學選課顧問」的角色，以繁體中文回應，並輸出包含以下欄位的 JSON 結構：

  • suitable（boolean）：是否推薦修課
  • score（0–100）：個人化適合度分數
  • reason（string）：推薦或不推薦的具體理由
  • suggestions（string[]）：修課建議清單（如先修科目、注意事項等）

分析結果在前端以格式化卡片呈現，包含適合度分數的視覺化指示條（綠色 / 黃色 / 紅色）、詳細理由說明，以及可供點擊展開的建議清單。分析結果同時儲存至 ai_analyses 資料表，方便使用者日後查閱歷史記錄。

為防止 AI 回應格式不穩定，後端設有 JSON 解析容錯機制：若 AI 未正確回傳 JSON 格式，系統將嘗試以正規表達式提取 JSON 區塊，並在所有解析方法均失敗時，以純文字形式呈現分析結果，確保使用者不會看到空白或錯誤畫面。

4.7　AI 排課規劃器

AI 排課規劃器讓使用者以自然語言描述修課目標，系統根據描述自動從全校課程資料庫中篩選並推薦最適合的課程組合。功能流程如下：

  1. 使用者在規劃器輸入框描述背景與目標（例如：「我是資工大二，想加強後端開發與資料庫能力，每週課最多排 4 天」）
  2. 前端呼叫 /api/planner-keywords，AI 分析描述並提取關鍵字（如「後端」「資料庫」「Node.js」），同時為每個關鍵字評分（0–1 權重）
  3. 前端利用關鍵字權重與 TAG_SYNONYM_MAP 同義詞對照表，對全校課程進行批量評分，找出最高分的前 N 門課
  4. 排課規劃器自動偵測課程時間衝堂（以節次陣列交集判斷），確保推薦組合在時間上可行
  5. 結果以視覺化週課表呈現，每門課以不同顏色區塊顯示，點擊可展開課程詳情

PDF 課表上傳：使用者亦可上傳現有課表的 PDF 檔案，系統透過 /api/planner-pdf 端點呼叫 OpenRouter OCR 引擎解析課程內容，自動填入排課規劃器，作為「已排課程」的基礎，再由 AI 在空閒時段中補充推薦新課程。

排課計畫可儲存至資料庫（planners 表），系統最多保留最近 5 份計畫（超過時自動刪除最舊的），避免資料庫無限增長。

4.8　Dcard 評分爬蟲

為提供學長姐的真實修課心得作為選課參考，本系統開發了一套 Dcard 自動爬蟲（scripts/crawl-dcard.mjs），定期蒐集逢甲大學 Dcard 版的相關文章，並透過 AI 彙整出結構化的課程評價資料。

爬蟲流程：

  1. 透過 Dcard API 搜尋逢甲版（fcu）中與選課相關的文章，關鍵字包含「修課」「心得」「推薦」「老師」等
  2. 過濾並去重複，保留含有明確課程名稱與教師名稱的文章
  3. 將每篇文章內容送至 AI 進行分析，提取以下資訊：
    • 課程名稱與授課教師
    • 課程標籤（難度、出席要求、評分方式等）
    • 綜合評分（0–100 分制）
    • 學生星等評價（1–5 星）
    • 簡要心得摘要
  4. 將結構化資料寫入 course_dcard_profile 資料表，若已有該課程記錄則執行 UPSERT 更新

前端展示：課程卡片上的 Dcard 評分區塊顯示星等（⭐ 1–5）與分數（0–100），並在 hover 時展示心得摘要文字，讓學生在瀏覽課程清單時即可快速掌握社群口碑。

4.9　核心程式碼（一）
（1）AI 多提供者切換機制（server.js）

系統依環境變數自動切換 AI 提供者，對外提供統一的 callAI() 函式介面：

async function callAI(prompt, systemPrompt = "") {
  if (AI_PROVIDER === "anthropic") {
    const response = await fetch(
      "https://api.anthropic.com/v1/messages",
      {
        method: "POST",
        headers: {
          "x-api-key": ANTHROPIC_API_KEY,
          "anthropic-version": "2023-06-01",
          "content-type": "application/json",
        },
        body: JSON.stringify({
          model: "claude-haiku-4-5",
          max_tokens: 2048,
          system: systemPrompt,
          messages: [{ role: "user", content: prompt }],
        }),
      }
    );
    const data = await response.json();
    return data.content[0].text;
  } else {
    // OpenAI-compatible (OpenAI / OpenRouter)
    const response = await fetch(`${OPENAI_BASE_URL}/chat/completions`, {
      method: "POST",
      headers: {
        Authorization: `Bearer ${OPENAI_API_KEY}`,
        "content-type": "application/json",
      },
      body: JSON.stringify({
        model: process.env.OPENAI_MODEL || "gpt-4o-mini",
        messages: [
          { role: "system", content: systemPrompt },
          { role: "user", content: prompt },
        ],
      }),
    });
    const data = await response.json();
    return data.choices[0].message.content;
  }
}

function hasTimeConflict(courseA, courseB) {
  const timesA = parseCourseTimes(courseA);
  const timesB = parseCourseTimes(courseB);
  return timesA.some(a =>
    timesB.some(b => a.day === b.day &&
      a.periods.some(p => b.periods.includes(p)))
  );
}
